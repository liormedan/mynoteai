mynoteai — תוכנית פיתוח

מחברת אישית בסגנון Notion, בקוד פתוח, שכל מפתח מתקין לעצמו ב-Vercel וב-Firebase. עודכן: 5.10.2026

החלטות מאגרים ספרינטים גרף גיט ובקרה סיכונים שאלות פתוחות

החלטות יסוד

מסגרת
Next.js 16 (App Router) + TypeScript
עורך
BlockNote 0.55 (ליבה, MPL-2.0)
נתונים, התחברות, קבצים
Firebase (Firestore + Auth + Storage)
ממשק
Tailwind + shadcn/ui
פריסה
Vercel, פריסה אוטומטית מ-main
רישיון המאגר
MIT
  • לא בונים עורך לבד. העורך הוא רוב העבודה בפרויקט כזה, ו-BlockNote נותן אותו מוכן: תפריט /, גרירת בלוקים, קינון, טבלאות ותמונות.
  • לא לוקחים מערכת שלמה. AppFlowy, AFFiNE, Docmost ו-Outline דורשים שרת קבוע עם Docker ולא רצים ב-Vercel.
  • לא משתמשים בחבילות @blocknote/xl-*. הן ברישיון GPL-3.0 ויכפו את הרישיון על כל המאגר. את הבינה המלאכותית בונים ישירות עם Vercel AI SDK, וייצוא נעשה ל-Markdown עם פונקציות הליבה.
  • מודל הפצה: משתמש יחיד לכל התקנה. המאגר הוא קוד פתוח שמפתחים מורידים ומתקינים כמחברת עצמאית, עם חשבון Vercel ופרויקט Firebase משלהם. אין שרת מרכזי, אין הרשמה ואין ריבוי משתמשים. ההתחברות קיימת רק כדי לנעול את ההתקנה לבעלים שלה.
  • חוויית ההתקנה היא חלק מהמוצר. pnpm dev רץ מול Firebase Emulator בלי שום חשבון, וסקריפט התקנה מחבר לענן. היעד: ממאגר נקי למחברת שעובדת ב-Vercel תוך 15 דקות.
  • עברית ואנגלית מהיום הראשון. הממשק דו-לשוני עם next-intl, וכיוון הדף (dir) נקבע לפי שפת הממשק. התוכן עצמו מקבל כיוון לפי כל בלוק, כך שאפשר לכתוב עברית בממשק אנגלי ולהפך. shadcn/ui מוגדר עם rtl: true, ל-BlockNote יש מילון עברי מובנה (he), ובקוד משתמשים רק במחלקות לוגיות (ms-, pe-, start-) ולא ב-ml- / right-.
  • שפת המאגר: README, מדריך ההתקנה, הערות בקוד והודעות קומיט — באנגלית, לקהל המפתחים. יש גם README.he.md ומדריך התקנה בעברית. התוכנית הזו ו-CLAUDE.md נשארים בעברית.
  • Firebase כי זה מה שעובדים איתו בשאר הפרויקטים. הקוד בצד הלקוח מדבר ישירות עם Firestore דרך כללי אבטחה, ונתיבי שרת ב-Next.js משתמשים ב-Admin SDK רק למה שחייב שרת: עוגיית התחברות, בינה מלאכותית, פרסום ציבורי.
  • תוכן העמוד נשמר כ-JSON של BlockNote במסמך נפרד מהמטא-דאטה של העמוד, כדי שטעינת העץ בסרגל הצד לא תמשוך את כל התוכן. במקביל נשמר טקסט שטוח לחיפוש.
  • ל-Firestore אין חיפוש מלא בטקסט. למשתמש יחיד בונים אינדקס בדפדפן (FlexSearch). אם יהיו הרבה משתמשים — הרחבה של Typesense או Algolia.

ספרינטים

ספרינט = שבוע עבודה בערך. כל ספרינט נגמר בגרסה שעובדת ופרוסה ב-Vercel, ונבדק בממשק עברי וגם בממשק אנגלי. הסטטוס של כל משימה נגזר מ-git בלבד, לא מסימון ידני — ראו גרף גיט ובקרה.

אין נתוני התקדמות. מריצים node scripts/plan-check.mjs --write ומרעננים את הדף.

תשתית ובדיקת עברית

שלד ריק שעולה ל-Vercel, ותשובה ברורה: האם BlockNote עובד טוב בעברית.
  • S0-1מאגר ציבורי ב-GitHub עם רישיון MIT, README ותוכנית
  • S0-2שלד Next.js 16 + TypeScript + Tailwind + shadcn/ui, עם pnpm
  • S0-3ESLint, Prettier, ובדיקות Vitest ריקות שרצות
  • S0-4GitHub Actions: בדיקת טיפוסים, lint ובנייה על כל PR
  • S0-5חיבור הפרויקט ל-Vercel ופריסה ראשונה
  • S0-6עמוד ניסוי עם BlockNote: כתיבה בעברית, ערבוב עברית ואנגלית, רשימות, גרירת בלוקים, תפריט /, טבלה
  • S0-7כיוון לכל בלוק לפי התוכן (dir="auto") ובדיקה שתפריט הצד נמצא בצד הנכון
  • S0-8תשתית שפות: next-intl עם he ו-en, <html lang dir> לפי השפה, מעבר שפה בממשק, ומילון BlockNote בשפה הנבחרת
  • S0-9כללי RTL בקוד: shadcn/ui עם rtl: true, ובדיקת lint שנכשלת על מחלקות פיזיות (ml-, pr-, left-, text-right)
שער החלטהאם העברית ב-BlockNote שבורה ואין לה תיקון סביר — עוברים ל-Tiptap עם ממשק משלנו, והספרינטים 2–3 מתארכים בשבועיים.

בעלים יחיד ומבנה נתונים

רק הבעלים של ההתקנה נכנס, ומפתח חדש יכול להריץ הכול מקומית בלי חשבון.
  • S1-1פרויקט Firebase, ומשתני סביבה ב-Vercel (הגדרות לקוח + חשבון שירות ל-Admin SDK)
  • S1-2התחברות עם Google ועם קישור במייל דרך Firebase Auth
  • S1-3מבנה נתונים למשתמש יחיד: pages/{pageId} עם title, icon, coverUrl, parentId, position, type, isArchived, isFavorite, createdAt, updatedAt, ותוכן ב-pages/{pageId}/content/main עם blocks, plainText
  • S1-4בעלים יחיד: firestore.rules ו-storage.rules נוצרים מתבנית עם OWNER_EMAIL, ומאשרים גישה רק לאימייל הזה כשהוא מאומת. כולל בדיקת שדות וטיפוסים
  • S1-5firebase.json, firestore.rules, firestore.indexes.json ו-storage.rules במאגר, ופריסה שלהם עם firebase deploy
  • S1-6middleware עם next-firebase-auth-edge שמפנה משתמש לא מחובר לעמוד הכניסה, ודוחה כל מי שאינו OWNER_EMAIL
  • S1-7pnpm dev רץ כברירת מחדל מול Firebase Emulator עם נתוני דוגמה בעברית ובאנגלית — מפתח חדש מנסה את המחברת בלי שום חשבון
הגדרת סיוםבדיקות כללי אבטחה ב-Firebase Emulator (@firebase/rules-unit-testing) מוכיחות שמשתמש מחובר שאינו הבעלים לא קורא ולא כותב כלום. שכפול נקי של המאגר ו-pnpm dev מגיעים למחברת עובדת בלי חשבון ענן.

BlockNote עדיין בגרסה 0.x, ושינויים שוברים אפשרייםנעילת גרסה מדויקת, ועדכון רק בענף נפרד

      
רישיון: חבילות xl-* ב-GPL-3.0לא מתקינים אותן. בדיקה ב-CI שנכשלת אם הן מופיעות ב-package.json

      
Cloud Storage for Firebase דורש תוכנית Blaze (חשבון חיוב) מאז 3.2.2026, גם בשימוש קטן. מפתח שלא רוצה לחבר כרטיס אשראי לא יוכל להעלות תמונותStorage הוא רשות. בלעדיו המחברת עובדת, וההעלאה מוחלפת בהדבקת קישור. המדריך מסביר איך להפעיל Blaze עם התראת תקציב

      
התקנה מסובכת = אף אחד לא משתמש. Firebase + Vercel + Google sign-in הם הרבה צעדים למפתח חדשמצב אמולטור בלי חשבון מספרינט 1, סקריפט התקנה ומדריך בספרינט 9, ובדיקת התקנה נקייה ב-CI

      
Vercel ו-Firebase הם שני ספקים שהמפתח צריך לפתוח בהם חשבוןלבדוק בספרינט 9 אם Firebase App Hosting יכול להחליף את Vercel כאפשרות התקנה בספק אחד

      
מסמך ב-Firestore מוגבל ל-1MiB, ועמוד ארוך מאוד עלול לחרוגתמונות נשמרות כקישור ל-Storage, ובדיקת גודל לפני שמירה עם אזהרה למשתמש

      
Firestore גובה לפי קריאה, ועץ של מאות עמודים נקרא בכל טעינהמאזין אחד עם מטמון מקומי, ומטא-דאטה מופרדת מהתוכן
